# Test the Sentinel API

This guide and the Postman collection cover all **72 operations** in `docs/openapi.json`. These examples describe the supplied contract; they do not claim every production operation has been executed successfully.

## Postman: test each endpoint

1. Import `docs/sentinel.postman_collection.json` in Postman (desktop app, or web app with Desktop Agent).
2. Open the collection's Variables tab. Keep `baseUrl` as `https://sentinel-api.absg-ohos.cloud/api/v1`. Enter your own account `email` and `password` locally. Do not share or commit populated values or the resulting token.
3. Send **Auth → POST /auth/login**. Its post-response script saves the returned bearer token to the collection's `token` variable. Other protected requests inherit that token automatically.
4. Send **Account → GET /auth/me** (or find it by request name), then **Workspace → GET /workspaces**. Copy an authorized workspace's `id` from `data` into the collection's `workspace` variable. Folder labels follow the API tags.
5. Send GET requests first. Copy actual IDs from list results into `monitor`, `mention`, `cluster`, `alert`, `source`, `user`, `invitation`, `savedSearch`, and `subscriptionId` as needed. A missing ID is not a connectivity failure.
6. For search, send **GET /workspaces/{workspace}/search**. Start with `q=MTN` and `collapse=0`; other optional filters are unchecked in Params. Try a term from an existing mention. Add date, country, source, or language filters individually. Use `collapse=1` to group stories; do not send text `true` or `false` in this query field.
7. For each write request, review Body before Send. Required-field examples are supplied; PATCH examples change one field. The request description includes all allowed body fields and their constraints. Replace `REPLACE_ME` and empty variables with valid values. JSON body booleans remain `true`/`false`.

Run write and delete requests individually in a disposable workspace. Do not run the entire collection against production: it includes account password changes, emails/invitations, membership changes, logout, and permanent deletion. Use a test account and data you intend to change. Reset-password needs a real reset token; invitation operations need a real invitation token. Push subscription creation needs endpoint/p256dh/auth values generated by a browser PushSubscription; arbitrary strings do not verify push delivery. Test logout last, then sign in again.

For deletion, first create a disposable resource, verify it with GET, delete it, and verify that it is no longer available. For update/pause/resume/read operations, fetch the same resource afterwards and confirm the intended state changed. Create requests should return an ID that can be fetched in the same workspace.

## VS Code terminal: PowerShell example

Use your own credentials in the local terminal. `Get-Credential` avoids putting a literal password into command history. Do not paste tokens or passwords into chat.

```powershell
$base = "https://sentinel-api.absg-ohos.cloud/api/v1"
$credential = Get-Credential -Message "Enter your Sentinel email and password"
$loginBody = @{
  email = $credential.UserName
  password = $credential.GetNetworkCredential().Password
  device_name = "API test"
} | ConvertTo-Json
$login = Invoke-RestMethod -Method Post -Uri "$base/auth/login" -ContentType "application/json" -Headers @{Accept="application/json"} -Body $loginBody
$headers = @{Accept="application/json"; Authorization="Bearer $($login.token)"}
Invoke-RestMethod -Uri "$base/auth/me" -Headers $headers
$workspaces = Invoke-RestMethod -Uri "$base/workspaces" -Headers $headers
$workspaces.data | Format-Table id,name
$workspaceId = Read-Host "Paste the workspace ID to test"
$query = [uri]::EscapeDataString("MTN")
$result = Invoke-RestMethod -Uri "$base/workspaces/$workspaceId/search?q=$query&collapse=0" -Headers $headers
$result | ConvertTo-Json -Depth 12
```

For any row below, append its path to `$base`, replace `{...}` placeholders with real values, and use its HTTP method. For JSON writes, add `-ContentType "application/json" -Body ($body | ConvertTo-Json -Depth 12)` using the collection's example body. Public requests omit Authorization. PowerShell throws on HTTP errors; inspect the error response for validation details.

To exercise the frontend proxy instead of calling production directly, run `npm run dev` and change `$base` to `http://localhost:5173/api/v1`. Postman and PowerShell do not enforce browser CORS, so direct success alone does not test browser CORS.

## Interpret results

- **200/201/204:** compare with the operation's documented success status below; 204 has no JSON body. A 200 response with `data: []` means the API returned no matching rows, not a connection failure.
- **401:** absent, expired, invalid, or revoked token. Sign in again.
- **403:** account does not have permission for the workspace/action.
- **404:** missing resource, wrong workspace/ID, or unavailable route.
- **422:** invalid body/query; inspect `errors` and the schema in the request description.
- **429:** rate limit; wait before retrying.
- **5xx:** backend/proxy failure; inspect server logs and response. Never treat it as an empty result.

The supplied schema may omit some runtime error responses. Successful authentication does not imply permission to administer every workspace.

## Automated checks in this project

```sh
npm ci --include=dev
npm run lint
npm run build
npm test
npm run test:live
```

Install Playwright Chromium with `npx playwright install chromium` if the test runner reports a missing browser. The default suite tests the UI and proxy with controlled backend fixtures. The live check contacts production without credentials and expects 401 for `/auth/me` and 422 for an empty login; it does not create accounts or prove every authenticated endpoint works.
